# Aspire Dashboard — журналы и трассировки

Локальная панель получает OpenTelemetry от `api-gateway`, `auth-service`, `profile-service` и `skill-service`:
структурированные журналы HTTP-запросов, распределённые трассировки и HTTP-метрики.
Сервисы по-прежнему запускаются Docker Compose; отдельный Aspire AppHost не нужен.

## Запуск

Из корня репозитория:

```sh
docker compose up -d --build
```

- Сайт: http://127.0.0.1:8080
- Панель: http://127.0.0.1:18888
- [Структурированные журналы](http://127.0.0.1:18888/structuredlogs)
- [Трассировки](http://127.0.0.1:18888/traces)
- [Метрики](http://127.0.0.1:18888/metrics)

Порт панели меняется через `ASPIRE_DASHBOARD_PORT` в `.env`. Интерфейс и API
панели доступны без пароля только на `127.0.0.1`; OTLP-порты не опубликованы
на хост. Сообщение панели «Конечная точка не защищена» относится к этому
локальному режиму. Для удалённого показа используйте SSH-туннель либо настройте
аутентификацию панели и HTTPS, прежде чем открывать её наружу.

## Как показать Gateway заказчику

1. Откройте сайт, зарегистрируйтесь и войдите. В локальном Compose подтверждение
   email отключено, `AUTH_REQUIRE_CONFIRMED_EMAIL=false`.
2. В «Структурированных журналах» найдите `POST /api/auth/login` от `api-gateway`
   и `POST /auth/login` от `auth-service`. Обе записи содержат код ответа,
   время обработки и одинаковый `RequestId`.
3. Нажмите ссылку в столбце «Трассировка». На диаграмме видна настоящая цепочка:
   входящий запрос Gateway → `proxy.forwarder` → HTTP-запрос к Auth → Auth Service.
   Длительности показывают, где запрос провёл время.
4. Повторите вход с неправильным паролем. В журналах появятся две записи уровня
   `Warning` с ответом `401`, связанные отдельной трассировкой. В HTTP-трассировках
   `401` может не считаться ошибкой span: для поиска используйте журнал `Warning`.
5. В разделе «Метрики» выберите ресурс `api-gateway` или `auth-service`:
   затем выберите слева `http.server.request.duration`, чтобы открыть график
   длительности запросов. Также доступны активные запросы и соединения.

HTTP-ответ возвращает `X-Request-ID` и `X-Trace-ID` — один стандартный W3C TraceId
из 32 шестнадцатеричных символов. Его можно скопировать из DevTools → Network →
`login` → Response Headers. Для точного поиска откройте:

```text
http://127.0.0.1:18888/structuredlogs?traceId=<TraceId>
http://127.0.0.1:18888/traces/detail/<TraceId>
```

## Настройка и границы

При сохранении профиля на сайте появляется `PUT /api/profile/me`. Его трассировка
содержит три ресурса: `api-gateway`, `profile-service`, `auth-service` — последний
проверяет действующую сессию через `/auth/me`. Внутренняя очистка после удаления
аккаунта идёт отдельной трассировкой из фонового worker Auth.

Общая библиотека [ServiceDefaults](ServiceDefaults/TelemetryExtensions.cs) подключена
ко всем трём .NET-сервисам. Она экспортирует OTLP/gRPC на `aspire-dashboard:18889`.
Журналы и трассировки отправляются пакетами примерно раз в 0,5 секунды, метрики —
раз в 5 секунд. Если `OTEL_EXPORTER_OTLP_ENDPOINT` не задан, остаются JSON-журналы
консоли без отправки в панель. Образы сервисов собираются с контекстом из корня
репозитория, чтобы включить общую библиотеку.

Тела запросов, Authorization, cookies и значения query-параметров не записываются
в журнал запросов; из URL трассировок удаляется query string. Проверки `/health/*`
и `/api/health/*` исключены из HTTP-журналов и трассировок, чтобы не засорять показ.
Метрики HTTP включают проверки здоровья.

В этом варианте инструментированы Gateway, Auth и ProfileService. Nginx, браузер, SQL,
PostgreSQL и Mailpit не отправляют собственную телеметрию. Страница управления
ресурсами AppHost не подключена. Телеметрия панели хранится в памяти: перезапуск
контейнера очищает её; сохранённые выше скриншоты остаются в репозитории.

## Проверка

При запущенном локальном Compose:

```sh
node --test observability/tests/telemetry.test.mjs
```

Проверка создаёт временный аккаунт и удаляет его после завершения. Выполняются
успешный и отклонённый входы, запрос с Bearer/cookie и тестовым query-параметром.
Проверяются общий TraceId, цепочка родительских spans, связанные журналы обоих
сервисов, уровень `Warning` для `401`, наличие метрик и отсутствие секретов в
собранной телеметрии. Тест печатает ссылку на трассировку успешного входа.

Справка: [самостоятельный запуск Aspire Dashboard](https://aspire.dev/dashboard/standalone/),
[HTTP API телеметрии](https://aspire.dev/dashboard/apis/).

Импорт JSON также виден в Aspire: `POST /api/skills/admin/import` проходит через
Gateway → SkillService → Auth (проверка роли). PUT профиля дополнительно обращается
из ProfileService в SkillService за допустимыми навыками. Содержимое JSON-файла
в HTTP-логи не записывается; история импорта хранится в `skill.catalog_imports`.
