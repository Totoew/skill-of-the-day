# SkillService — справочник навыков

Сервис хранит канонические навыки, синонимы и принадлежность к направлениям,
включая признак базового навыка. Четыре проекта: Api, Application, Domain,
Infrastructure; один контейнер API. PostgreSQL — существующий `auth-db`,
собственная схема `skill`. Чужие таблицы сервис не читает.

## Запуск и интерфейс

```sh
docker compose up -d --build
```

- Админка: http://127.0.0.1:8080/#/admin
- Swagger (Development): http://127.0.0.1:8080/api/skills/swagger/index.html
- OpenAPI: http://127.0.0.1:8080/api/skills/openapi/v1.json
- Справочник: http://127.0.0.1:8080/api/skills/catalog
- Aspire: http://127.0.0.1:18888

Нужен аккаунт с ролью **Admin**. Настройка через `AUTH_ADMIN_EMAIL` и
`AUTH_ADMIN_PASSWORD` в локальном `.env` описана в
[Auth Service](../../../auth-service/README.md). После изменения этих параметров
пересоздайте контейнер: `docker compose up -d auth-service`. Регистрация обычного
пользователя не даёт прав администратора. Пароли в репозиторий не добавляются.

В панели «Справочник навыков · импорт JSON»:

1. Скачайте пример либо выгрузите текущий справочник.
2. Выберите JSON-файл UTF-8 размером до 1 МБ.
3. Нажмите «Проверить файл»: показываются ошибки или число добавляемых,
   обновляемых и неизменных записей. На этом шаге БД не изменяется.
4. Нажмите «Импортировать справочник». После подтверждённого ответа API список
   обновится; новые навыки доступны в настройках профиля. Другие открытые браузеры
   получают изменения при перезагрузке страницы.

Импорт работает с настоящей БД. Накопитель необработанных терминов и ручные
пометки вакансий в соседних блоках админки пока используют демонстрационные данные.

## Формат JSON v1

Полный стартовый пример: [catalog.example.json](catalog.example.json).
Небольшой файл для добавления одного навыка:

```json
{
  "schemaVersion": 1,
  "skills": [
    {
      "code": "postgresql",
      "name": "PostgreSQL",
      "synonyms": ["Postgres", "Postgre SQL"],
      "directions": ["analyst", "csharp"],
      "basicFor": []
    }
  ]
}
```

Все поля обязательны. Неизвестные поля отклоняются. `code` — постоянный
уникальный код до 64 символов: строчные латинские буквы, цифры, дефис; начинается
с буквы. Название и каждый синоним — непустая строка до 255 символов, без крайних
пробелов и управляющих символов. До 50 синонимов на навык, до 2000 навыков в файле,
до 10 000 в справочнике. У каждого навыка хотя бы одно направление.

Направления: `analyst`, `csharp`, `qa`. `basicFor` — подмножество `directions`;
пустой массив означает специализированный навык. Регионы, уровни и определения
направлений принадлежат другим справочникам и в этот импорт не входят.

Название и синонимы не должны повторяться внутри файла или конфликтовать
с итоговым справочником. При сравнении применяется Unicode NFKC, игнорируются
регистр и повторные пробелы. Синоним может принадлежать только одному навыку.
Хранение словаря само по себе не реализует разбор текстов вакансий.

Импорт **добавляет и обновляет по `code`**. Для включённой записи массивы синонимов,
направлений и базовых направлений заменяются целиком. Записи, не включённые в
файл, сохраняются. Каноническое имя существующего кода менять нельзя: профили
пока хранят названия навыков. Переименование потребует отдельной миграции ссылок.
Дублирующий тот же навык новый код также отклоняется.

## API через Gateway

| Метод | Путь | Доступ |
| --- | --- | --- |
| GET | `/api/skills/catalog` | Публичный справочник с `version` |
| GET | `/api/skills/admin/template` | Admin, пример файла |
| GET | `/api/skills/admin/export` | Admin, текущий справочник без служебной версии |
| POST | `/api/skills/admin/import/preview` | Admin, тело — JSON v1 |
| POST | `/api/skills/admin/import` | Admin, тело — `{ "catalog": <JSON v1>, "version": <версия проверки> }` |

Ошибки формата — `400` (детали в `errors`), конфликт со справочником или устаревшая
версия — `409`, отсутствие сессии — `401`, обычный пользователь — `403`.
Лимит HTTP-тела сервиса — 1 100 000 байт; превышение — `413`.
При недоступном Auth сервис закрывает защищённые операции с `503`.

Все защищённые запросы проверяют действующую сессию и роль через `/auth/me`.
Отозванный JWT не даёт доступ. Swagger Authorize использует `accessToken`
администратора и сервер `/api`; токен не сохраняется между перезагрузками.

Импорт выполняется одной транзакцией с общей блокировкой и проверкой версии:
ошибка не оставляет частично записанного файла. Одновременные изменения требуют
повторной проверки. Повторный импорт без изменений не увеличивает версию.
`skill.catalog_imports` хранит UUID инициатора, время и числа изменений; исходный
файл и содержимое запросов не пишутся в HTTP-журналы. Записи импорта пока не имеют
автоматической очистки.

## Начальные данные и миграции

Локальный Compose включает `Skill__AutoMigrate=true`, `Skill__SeedDemoCatalog=true`.
Пример из 18 навыков загружается только при пустом справочнике версии 0. Это
стартовый демонстрационный набор, а не утверждённая таксономия. Повторный запуск
не восстанавливает и не перезаписывает пользовательский импорт.

Старые ID навыков и образовательные материалы сохраняются. Старые записи без
кода получают `legacy-<id>`; их связи с направлениями можно добавить импортом.
Если в старой БД есть дубли, уникальные индексы останавливают миграцию: требуется
явное исправление, данные автоматически не удаляются. История FluentMigrator
общая `VersionInfo`, сканируется только Infrastructure этого сервиса.

Для сервера задайте `ConnectionStrings__SkillDb`, `Database__Password`,
`Auth__Address`; примените `dotnet SkillService.Api.dll --migrate` одним процессом,
затем запускайте API с `Skill__AutoMigrate=false`. `Skill__SeedDemoCatalog=false`
оставляет наполнение администратору. Миграции создают схему в уже существующей БД.

Фронтенд загружает справочник при запуске. ProfileService проверяет сохранение
навыков по `GET /skills/catalog` через `Skills__Address`; недоступность справочника
даёт `503`, без сохранения непроверенных настроек. Вакансии по-прежнему демонстрационные;
roadmap рассчитывает RecommendationService по текущему справочнику. Импорт не создаёт вакансии или их требования.

## Проверки

```sh
node --test backend/Services/SkillService/tests/catalog.test.mjs
cd frontend
SKILL_INTEGRATION=1 PLAYWRIGHT_BASE_URL=http://127.0.0.1:8080 npm run test:e2e -- --grep 'Real SkillService'
```

API-тесты проверяют права, формат, атомарность, идемпотентность, перенос синонима,
конфликты версий, экспорт, Swagger и сохранение нового навыка в профиле.
Браузерный тест проходит загрузку файла и сохранение профиля. Только временный
тестовый аккаунт получает Admin через локальный `docker compose exec auth-db`.
Тестовые записи имеют уникальный префикс и удаляются после проверки; существующие
аккаунты и значения не изменяются. Запускать против локального тестового Compose.
